# Участие в разработке

Проект распространяется под [AGPL-3.0](./LICENSE); отправляя изменения, вы соглашаетесь на ту же лицензию.

## Окружение

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
```

## Перед pull request

1. Прогоните тесты — они должны быть зелёными:

   ```bash
   python -m pytest -q
   ```

2. Новый код и исправленный баг сопровождайте тестом.
3. Если менялись настройки в `config/settings.py`, обновите пример окружения: `python cli.py env-example > .env.example` (тест сверяет файл с генерацией).

## Golden-снапшоты

`tests/test_golden.py` сравнивает вывод генераторов с эталоном в `tests/golden/snapshots/`. Расхождение — не повод молча перезаписывать эталон. Если изменение вывода намеренное, обновите снапшоты (`python tests/golden/harness.py . tests/golden/snapshots`) и опишите расхождение в [tests/golden/ALLOWED_DIFFS.md](./tests/golden/ALLOWED_DIFFS.md): что изменилось и почему.

## Шаблоны и профили

- В `templates/` и `profiles/example-*.yaml` не должно быть персональных данных: реальных имён, брендов, каналов, доменов, токенов, IP-адресов. Используйте вымышленные значения (`example.com`, `@example_*`).
- Тексты для читателя живут в шаблонах, а не в `.py`. Факты о бренде берутся из полей профиля.
- Не коммитьте `.env`, `data/` и собственные профили (`profiles/<имя>.yaml`, `profiles/<имя>/`).

## Стиль

Небольшие сфокусированные PR. Не добавляйте зависимости без необходимости: LLM-клиент намеренно написан на стандартной библиотеке.
